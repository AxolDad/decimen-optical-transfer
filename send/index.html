Changes restart the stream — the receiver resets automatically (new session id in the frame headers; that's the fountain protocol's gift). Frames are held for a whole number of display refresh cycles, so the actual fps (shown above) is the nearest exact division of your screen's refresh rate. Grids multiply data per frame but shrink the modules — get closer or use a bigger display.
Encrypt for YouTube seals the file and records a transcode-hardened clip: big modules, a slow code rate so each code spans several video frames, high error-correction, and heavy fountain redundancy, rendered at 4K. The codec's damage lands on frames the fountain can spare — not on your file. Upload it, keep the key, and only the key opens it. (Measured: a sealed clip re-encoded through simulated AV1, VP9 and H.264 ladders decodes byte-exact at every rung from 2160p down to 480p — so download at 480p or better. That simulates the codecs YouTube delivers; it is not a YouTube round-trip. Treat it as a durable second copy, not your only one.)
Max screen brightness helps. The stream loops forever — stop when the receiver says done. Drop any file anywhere on this page to send it; name and type travel inside the stream, and compressible files are deflated on the fly. Sealed streams are ciphertext end to end — export one as a video and host it anywhere; only the key opens it.
