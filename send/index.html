Settings
  • Changing anything restarts the stream, and the receiver resets itself off the new session id. That's the fountain protocol's gift.
  • Frames are held for whole refresh cycles, so the actual fps shown above is the nearest exact division of your screen's refresh rate.
  • Grids multiply data per frame but shrink the modules. Get closer, or use a bigger display.

Encrypt for YouTube

Seals the file and records a clip built to survive being re-encoded, so the codec's damage lands on frames the fountain can spare rather than on your file.

  • Big modules and a slow code rate, so each code spans several video frames instead of one.
  • Error correction raised to Q, because a codec channel is corruption-dominant where the camera channel is erasure-dominant.
  • Heavy fountain redundancy, rendered at 4K.
  • Measured: byte-exact down to 240p against simulated AV1, VP9 and H.264 ladders, breaking at 144p.
  • Download at 480p or better. Two rungs above the measured floor, deliberately, because per-title encoding moves the real bitrate by over 400%.
  • Not a YouTube round-trip. That simulates the codecs YouTube delivers. Treat the clip as a durable second copy, not your only one.

While it runs

  • Maximum screen brightness helps.
  • The stream loops forever. Stop when the receiver says it's done.
  • Drop any file anywhere on this page to send it. Name and type travel inside the stream, and compressible files are deflated on the fly.
  • Sealed streams are ciphertext end to end, so an exported clip can be hosted anywhere and only the key opens it.
