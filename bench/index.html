Decimen loopback bench

Runs the real encode → QR → zxing-worker → fountain pipeline against synthetic frames on this device's CPU. No camera, no second device.

  • Finds the decode ceiling for whatever hardware you open it on, which is the number that caps everything else.
  • Answers optics or CPU. If a real transfer is slow but the bench is fast, the problem is how you're holding the phone.
  • A/B tests decoder settings without the variance a handheld camera adds to every measurement.
  • Open it on the receiving device. A laptop's numbers say nothing useful about a phone's.
Configuration
  • tight crop measures pure decode cost, matching a receiver that has already locked on and is cropping to the code.
  • 1280 and 1920 reproduce full-capture decode, before a lock narrows the search.
  • Frame synthesis runs on the main thread, so with many fast workers the pipeline can be generation-bound rather than decode-bound. The report says which it was.
