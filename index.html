Decimen fountain-coded optical transfer

YouTube as a dead drop. Encrypt a file, post it anywhere as a stream of animated light, and only the key holder can ever open it — no network, no account, no trace of what it is.

Underneath that: a file crosses between two devices using nothing but a screen and a camera. One displays it as an endless stream of QR codes, the other watches and reconstructs it. There is no network path between them, no pairing step, and no permission beyond the camera. The payload travels as light.

Open one on each device

Send The device holding the file — a laptop is ideal. Starts streaming immediately; drop any file onto the page to send it. Receive The device with the camera, usually a phone. Point it at the flickering code and hold steady, or prop it against something.

Why it survives a channel this bad

A screen-to-camera link has no back-channel: the receiver cannot ask for a frame again, and it will miss plenty of them to blur, refresh straddling and autofocus hunting. So no frame is any particular part of the file. Each one is a fountain-coded combination of a random subset of blocks, and collecting any sufficient number of them, in any order, reconstructs the original. Dropped frames cost a little time and never cost correctness — the two devices never even agree on a frame rate.
